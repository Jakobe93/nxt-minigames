Install

ensure ox_lib
ensure nxt-minigames

On start the server prints [nxt-minigames] v1.6.0 started — 21 minigames enabled. If that version doesn't match the build you expect, you're running a stale copy.

Which export to use

Anything that grants items, money, access or progress → server Run. The server opens the session, and the result is decided server-side. Your resource never takes the client's word for it.

Client Start is for things with no payoff: flavour, practice, or a door animation where the server re-checks separately. A client-side true must never be forwarded to the server as proof.

Server

-- Yields until the player finishes. ok: boolean, info: { reason?, ms? }
local ok, info = exports['nxt-minigames']:Run(source, 'keymatrix', 6)
-- optional fourth argument: options for this call only
local ok2 = exports['nxt-minigames']:Run(source, 'crawler', 5, { theme = 'nxt' })
if ok then
    exports.ox_inventory:AddItem(source, 'usb_decrypted', 1)
end

-- Non-yielding
exports['nxt-minigames']:RunAsync(source, 'cipher', 4, function(ok, info) end, { theme = 'terminal' })

exports['nxt-minigames']:IsBusy(source)   -- true while a session is open
exports['nxt-minigames']:GetGames()       -- { { id, label }, ... } enabled only

Code game on a keypad prop (nxt-dui)

Cipher Lock's scoring for a keypad another resource draws. The code never leaves the server; the colours follow Wordle's rule for repeated digits.

-- server: make a code (difficulty 1-10, length = the keypad's tiles)
local id, tries = exports['nxt-minigames']:CodeStart(source, 5, 4)

-- server callback the keypad's onGuess calls
local tiles, status = exports['nxt-minigames']:CodeGuess(source, id, guess)
-- tiles 'gyxx' (g right place, y elsewhere, x not in it); status nil | 'cracked' | 'out'

-- client
NxtDui.codepad({
    entity = keypad,
    tries = tries,
    onGuess = function(guess)
        return lib.callback.await('my_res:guess', false, keypadId, guess)
    end,
})

Client

local ok = exports['nxt-minigames']:Start('signal', 3)   -- yields; call from a thread
local ok2 = exports['nxt-minigames']:Start('echo', 4, { theme = 'sampler' })
exports['nxt-minigames']:IsOpen()                         -- minigame or viewer on screen
exports['nxt-minigames']:Stop()                           -- end the minigame on screen as a fail

Result hook

Every closed session fires a server-local event. It isn't a net event, so clients can't fake it. Use it for logs, dispatch or analytics.

AddEventHandler('nxt-minigames:server:result', function(src, r)
    -- r = { id, difficulty, ok, reason, ms, origin = 'server' | 'client' }
end)

Every tunable is { value at D1, value at D10 } and is linearly interpolated. Rule-style switches (hidden output on Key Derivation D7+, lookalike decoys on Intercept D6+, and so on) are fixed in the game code.

Themes

Which look a session gets, first match wins:

  1. the calling script's { theme = '...' } for that call (any name in Config.Themes: nxt, terminal, synthwave, tactical, telegraph, sampler, arcade, club; an unknown name is ignored);
  2. the game's own look (Memory Diff terminal, Ping Ball arcade, the five rhythm games one each);
  3. Config.Theme (default terminal).

In the viewer, AUTO shows each game's own look and the other buttons force one look on every game.

Reduce motion: when nxt-hud's switch is on (exports['nxt-hud']:isReduceMotion()), shakes, tile flips, sparks, the club floor and other ambient flashing stop. Beat cues the rhythm games need to be played stay.

Adding a theme: add a palette to THEMES in web/js/core.js (canvas colours, font, cable colours, overlay copy) and a body[data-theme=name] block in style.css that overrides the CSS variables. Canvas games read the palette at draw time and DOM games read the CSS variables, so no game file needs touching.

Fonts are self-hosted. JetBrains Mono is a custom subset (Latin plus arrows ← ↑ → ↓ and typographic punctuation) built from the official release with pyftsubset, because the stock Latin subset lacks ← and →.

Staff viewer

Admin menu > SCRIPTS > Minigames > Open editor (nxt-admin). The rank permission is "Open Minigames" (module.nxt-minigames), turned on in nxt-admin's rank editor. nxt-admin checks the staff session and the permission, logs the opening, then calls this resource's adminOpenViewer export. Server console when nxt-admin is down: minigames_viewer <player id>. Viewer runs never open a session, so they can't satisfy Run or Start.

Opening web/index.html in a normal browser boots straight into the viewer, which is handy for UI work without a server.

Security model

  • Tokens are one-shot, bound to the player's server id, and expire server-side.
  • One session per player. Client-started sessions are rate-limited (ClientStartCooldownMs).
  • A pass faster than minSolveMs is rejected. The timer starts at issue, so intro time only makes the floor more lenient.
  • Cipher Lock's code never reaches the client: each guess goes to nxt-minigames:cb:cipher, which answers the colours, and a pass is accepted only after the server scored the right code.
  • Everything a cheater could use is in server/config.lua, never downloaded by a client.
  • Impossible input fires the server-only local event nxt:flag: minigames.foreign_token, minigames.too_fast (under half the limit only), minigames.cipher_unsolved, minigames.bad_guess, minigames.guess_wrong_game.
  • nui_callback_strict_mode is on.
Known limit: the puzzles are generated and checked in the NUI. A modified client that waits out the floor and then reports a pass will still get through. Floors, one-shot tokens and rate limits stop event injection and scripted spam. They don't stop a determined cheater. Cipher Lock is now checked on the server. The other deterministic games (Key Matrix, Key Derivation, Signal Path, Memory Diff, Patch Panel) can follow the same pattern; not built.

Open [VERIFY] items

  • None of the 1.3.0 layouts or the eight new games have been played in game. The rhythm games' audio timing in the game's browser is untested; Config.AudioOffsetMs is there if the beat sounds late.
  • All minSolveMs floors are estimates from headless play. Watch for too_fast warnings on legit players and loosen those games.
  • All difficulty curves are first-pass. D9–10 on Cipher Lock, Key Derivation and Packet Audit need real play-testing.
  • In-CEF behaviour of Esc and right-click (Port Sweep flags, Signal Path rotate-back) is untested outside Chromium.
